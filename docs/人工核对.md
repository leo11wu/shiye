# 样页与独立人工核对

本次交付没有上传书页、没有真实云端 OCR 结果，CER 和特殊字形准确率均未验收。自动化协议测试、已知文字排版样张及 AI 转写都不能替代独立人工金标。

用户配置 API 后，Bodman 首轮可选原 PDF 第 6、40、80 页，再加入封面、空白页和连续五页正文。开发样页为 1、6、10、20、40、80、155；独立核对页为 15、30、60、100、120、140。项目页序与原书印刷页码分别记录。若使用导出的子集，须保留子集页码映射。

## 准备核对材料

从保存的项目生成清单：

```bash
python3 scripts/audit_cer.py template '/项目路径/document.json' '/核对目录/gold.json'
```

核对者直接查看原扫描，逐单元填写 `gold_text`，确认后才将 `verified_by_human` 设为 `true`。API 原始转写和用户修改版分别保留为候选，不可把候选直接复制成独立金标。

检查原页的每一处可见正文。OCR 没有检测到的区域必须手工增加记录，候选文字留空；否则漏块不会进入错误率。作为原图保留的文字表格也必须计入核对，不能从分母移除。真实插图的无文字部分不进入字符错误率。核对范围的文字完整性经过人工确认后，才设置 `coverage_verified_by_human: true`。

至少核对 5,000 个正文字符；至少核对 200 处特殊字形，分别记录音标、送气、声调、长音、组合附标、上下标、异体字和罕见汉字。特殊项记录 `special_occurrences`、`special_types` 与 `confirmed_special_errors`；未知保持空值，不能当作零错误。

```bash
python3 scripts/audit_cer.py score '/核对目录/gold.json' '/核对目录/cer-report.json'
```

CER 使用编辑距离除以金标字符数，仅统一 NFC 等价形式和版式空白。不删除附标、异体字、音标或疑难项。候选留空时，金标字符计为删除。未人工确认的单元单列，不能把部分核对结果称为整份文献验收通过。

程序的 `accepted` 只表示所提供核对材料满足数量、完整性声明和数值门槛；它不能验证核对者身份、专业能力或所填金标的正确性。另需实际连续阅读五页，检查脚注归属、表格行列、复制顺序、原页映射及疑难密度。样页通过后再扩大处理。
